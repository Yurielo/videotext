# videotext

Фирменный знак VideoText объединяет воспроизведение видео, строки расшифровки и аудиоволну. Мастер-логотип хранится в `Resources/Branding/VideoTextLogo.png`, а `Resources/AppIcon.icns` используется Finder, Dock и шапкой приложения.

`videotext` — нативное macOS-приложение SwiftUI для локальной расшифровки и обработки видео или аудио.

После выбора медиафайла приложение автоматически создаёт рядом проект:

```text
Обработка видео <название файла>/
├── Video/
├── Texts/
└── Support files/
```

Версия 0.6.1 хранит историю заданий, открывает legacy-проекты и позволяет продолжить прерванную обработку. Проектная schema v7 ведет отдельные артефакты, ревизии и зависимости для русского и английского языков; перевод или производное видео не перезаписывают оригинал.

В списке операций полного проекта показываются пользовательские команды расшифровки, перевода, тематического таймкодинга и прожига субтитров. Диагностика, определение языка, контроль качества, манифест, временная шкала, `ffprobe` и обнаружение результатов добавляются `WorkflowEngine` по зависимостям. Если готовый SRT пригоден, отсутствующий или устаревший transcript восстанавливается без повторного запуска Whisper.

Для открытия существующего проекта можно выбрать его корневую папку, `Support files`, файл `manifest.json`, `Video`, `Texts` или родительскую папку, содержащую один проект videotext.

В панели «Фрагмент» диапазон выбирается по таймкоду, теме или двум цитатам. Язык и детализация topic-набора задаются отдельно; detailed, normal и coarse хранятся в разных файлах. Неоднозначный поиск цитат предлагает варианты с контекстом. Поля времени принимают секунды или формат `ЧЧ:ММ:СС.ммм`, а SRT фрагмента пересчитывается относительно его новой временной шкалы.

Команда «Создать итоговый вариант» применяет к любой из трёх вырезок один упорядоченный рецепт: mute слов-паразитов, изменение скорости, статический blur и прожиг субтитров. Все эффекты подключаются независимо, blur выключен по умолчанию, а итоговые `fragment_processed.mp4`, синхронизированный SRT и JSON-рецепт сохраняются рядом с фрагментом; временные промежуточные файлы удаляются после строгой проверки.

Отдельные панели создают варианты полного видео или последнего фрагмента: изменение скорости 0.5x-2.0x, статический blur, watermark из PNG/JPEG/WebP, улучшение звука, mute выбранных слов-паразитов и нейтральный мужской дубляж. Для EN используется системный `Daniel (Enhanced)`, для RU временно выбран `Yuri (Enhanced)` с возможностью будущей замены. Watermark может объединить blur, overlay и субтитры в одном порядке фильтров. Параметры и provenance сохраняются в `manifest.json`; исходные медиа, звук, transcript и SRT не изменяются.

Whisper сохраняет word-level JSON с confidence и отчет качества. Для новых расшифровок используется прошедшая RU/EN benchmark Silero VAD; при ошибке её загрузки Whisper один раз повторяет операцию со стандартной сегментацией. Сомнительные cue не блокируют pipeline: для них создаются задания ручной проверки, а в интерфейсе и HTML-отчете они выделяются красным с дополнительной текстовой меткой. Перевод `ru -> en` и `en -> ru` сохраняет исходное число cue и временные границы; невалидные пакеты не принимаются молча.

Для новых проектов Human Review исходной расшифровки включён по умолчанию и может быть отключён до запуска. Включаемый анализ слов-паразитов также активен по умолчанию и выполняется до checkpoint. Затем `WorkflowEngine` сохраняет очередь оставшихся операций, приостанавливает обработку, подаёт звуковой сигнал и автоматически открывает вкладку встроенного редактора. В ней доступны все cue: найденные ошибки и слова-паразиты подсвечиваются, текст можно искать, прослушивать и исправлять. В первой версии нельзя менять количество, порядок, ID и временные границы cue; строгая проверка не даст утвердить такую правку. Черновики сохраняются отдельно, а субтитры, темы, перевод, дубляж и производные видео используют только утверждённую активную ревизию. После утверждения обработка автоматически продолжается с сохранённой очереди.

Новый проект использует русский язык распознавания по умолчанию; Auto и EN выбираются явно. Статический blur выключен до включения пользователем, режим mute по умолчанию охватывает все найденные слова-паразиты, а базовый размер шрифта субтитров равен 20.

Для переведённой расшифровки действует отдельный checkpoint перед созданием переведённых субтитров, тем и дубляжа. Он доступен для обоих направлений `ru -> en` и `en -> ru`, но по умолчанию выключен. Настройки обоих checkpoint сохраняются в `manifest.json`; незавершённая проверка восстанавливается после повторного открытия проекта.

Human Review тематического таймкодинга включён по умолчанию. После создания доступных наборов приложение открывает вкладку «Темы», где для каждого языка и уровня детализации можно просмотреть видео, изменить название и описание, перенести границу на существующий cue, разделить или объединить соседние темы. До утверждения создание производных файлов заблокировано. Schema v7 хранит независимые pending/approved snapshots всех topic-вариантов и рецепт итогового фрагмента; нарушение покрытия, порядка или cue-границ не может быть утверждено.

Нулевые служебные реплики, встречающиеся в SRT от Whisper, не считаются пользовательскими субтитрами и пропускаются с записью их количества в отчёт временной шкалы. Обратные интервалы, пересечения и выход за длительность медиа по-прежнему считаются ошибками.

В интерфейсе отображаются прогресс текущей операции и всего задания, прошедшее время и ETA на основе истории сопоставимых операций. До накопления достаточной выборки показывается «Оценка уточняется», а не недостоверное число. После завершения приложение отправляет системное уведомление со звуком и показывает встроенное окно результата.

Правая панель содержит сводку фактического состояния проекта. Она отдельно показывает готовность расшифровки, проверки временной шкалы, тематического таймкодинга, SRT, видео со вшитыми субтитрами и количество фрагментов. Дополнительный раздел показывает диагностику, манифест, `ffprobe` и обнаружение результатов. Состояния вычисляются по содержимому файлов и могут иметь значения «Готово», «Частично», «Отсутствует» или «Ошибка».

В 0.4.1 окно адаптируется к экрану от 980×680 pt: шапка переходит в две строки, а история, настройки и результаты имеют изменяемую ширину. Устаревший `topics.json` от `KeywordTopicAdapter` показывается как требующий пересчёта и не загружается в редактор тем. Актуальный качественный режим использует `HybridTopicAdapter`: смысловые абзацы SRT, `embeddinggemma`, проверку кандидатных границ Qwen/Gemma и точные времена исходных `cueId`.

Для операций, которым нужны расширенные фильтры, capability resolver в первую очередь проверяет `/opt/homebrew/opt/ffmpeg-full/bin`, затем Homebrew и системные пути. Диагностика фиксирует версии FFmpeg/ffprobe, Whisper, Ollama, модели, системные голоса и наличие обязательных фильтров. Команды обновления сохраняются как Terminal-задачи и не выполняются автоматически.

## Проверки разработки

Focused probes запускаются отдельными скриптами `scripts/test_*.sh`. Локально покрыты schema migration, RU/EN language detection, качество расшифровки, Human Review и блокировка таймкодов, review tasks, перевод, topic matrix, цитаты, скорость, blur, watermark, слова-паразиты и mute, единый рецепт фрагмента, улучшение звука, TTS, ETA и диагностика. Это deterministic-проверки; они не заменяют реальный model benchmark, listening QA и E2E на видео.

Перед выдачей сборки необходимо дважды выполнить:

```bash
scripts/test_e2e.sh <короткое-видео> <модель-whisper>
```

После любого исправления отсчёт чистых прохождений начинается заново. Сборка готова только после двух последовательных результатов `E2E PASS`.

Минимальная компоновка окна проверяется отдельным нативным probe:

```bash
scripts/test_layout.sh
```

Формат диапазона, длительности и длинного названия в списке тем проверяется
быстрым probe:

```bash
scripts/test_topic_picker.sh
```

Для релизной проверки используется единая команда. По умолчанию она создает и
проверяет отдельный candidate, не заменяя стабильную сборку:

```bash
scripts/release_gate.sh <короткое-видео> <модель-whisper>
```

После положительных verdicts reviewer, QA, CI/CD и Product Owner тот же
candidate можно продвинуть без пересборки:

```bash
scripts/release_gate.sh <короткое-видео> <модель-whisper> --promote
```

Команда сохраняет hashes, логи двух E2E, версии инструментов, bundle metadata
и итоговый статус в `work/release-gate/<дата>/evidence.env`. Обычная команда
`scripts/build_app.sh` собирает только временный app в `/private/tmp` и не
перезаписывает пользовательскую стабильную версию.

## Разработка с агентами

Проектный [`AGENTS.md`](AGENTS.md) подключает девять специализированных ролей
из [`.codex/agents/`](.codex/agents/README.md) к дальнейшей разработке.
Координатор выбирает ведущую роль по типу задачи, разделяет области записи,
подключает независимые QA/review/release-роли и применяет обязательный
release-gate перед выдачей `.app`.

Целостность интеграции проверяется командой:

```bash
scripts/check_agents.sh
```

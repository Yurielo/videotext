# Агенты разработки VideoText: модель v2

## Область действия

Product Owner руководит процессом как основной координатор текущей задачи:
фиксирует результат, scope, acceptance criteria и выбирает минимальный полезный
набор исполнителей. Отдельный запуск product-owner обычно не нужен.
Агент не заменяет человека в продуктовых решениях и не расширяет разрешенный scope.

## Основные роли

| Роль | Контракт | Когда применяется |
| --- | --- | --- |
| Product Owner / координатор | .codex/agents/product-owner.md | Ведение задачи в основном контексте; отдельный read-only советник только для сложного анализа |
| Application Developer | .codex/agents/application-developer.md | Сквозная реализация Swift/SwiftUI, workflow, адаптеров и файловых схем |
| QA Engineer | .codex/agents/qa-test-engineer.md | Независимая проверка существенных изменений поведения и каждого release candidate |
| Code Reviewer | .codex/agents/github-pr-reviewer.md | Независимое read-only ревью существенного production-diff |
| Release Engineer | .codex/agents/ci-cd-engineer.md | Сборочный процесс, подпись, упаковка и выпуск |

Идентификаторы QA, reviewer и CI/CD сохранены для совместимости.
Регистрации находятся в .codex/agents/*.toml; роли не являются фоновыми процессами.

## Маршрутизация и ответственность

- Узкая задача с полными критериями: координатор применяет инженерный контракт
  самостоятельно, выполняет релевантные проверки и обновляет документацию.
- Обычная функция: один application-developer владеет сквозной реализацией.
  QA проверяет существенное изменение поведения; reviewer отдельно анализирует
  существенный production-diff. Для небольшой правки отдельные запуски не обязательны.
- Межмодульная задача: координатор фиксирует контракты и риски. Число модулей
  само по себе не требует дополнительных агентов. Делегируется конкретная
  независимая работа, которая ускоряет выполнение или снижает риск.
- Планирование и документация входят в основную задачу. Специалист подключается
  эпизодически для большого плана или руководства.
- Релиз: независимые qa-test-engineer и github-pr-reviewer, затем ci-cd-engineer
  проверяют evidence; координатор сводит итог и соблюдает человеческую приемку.
  Недоступная обязательная роль не подменяется самопроверкой автора.
- QA проверяет поведение и негативные сценарии; reviewer анализирует diff.
  Их вопросы различаются. Блокирующее замечание исправляется и перепроверяется.

У каждого изменения один владелец реализации. Одновременная запись в один файл
запрещена. Общие схемы, ProjectLayout, миграции и persistence меняет назначенный
владелец последовательно. Тяжелые Whisper/Ollama/ffmpeg проверки, финальные E2E
и продвижение одной .app также выполняются последовательно.
Handoff содержит цель, критерии приемки, разрешенные файлы, запреты, результаты
проверок и оставшиеся риски. Отчет краткий; повторный пересказ контекста не нужен.

## Справочники и совместимость

Application Developer читает только применимые справочники:
docs/agents/pipeline.md, docs/agents/swiftui.md, docs/agents/persistence.md.

Старые роли backend-developer, frontend-developer, database-architect,
jira-sprint-planner и confluence-doc-writer остаются переходными регистрациями.
Их прежние контракты не удаляются и не переписываются. Они предназначены для
ранее выданных handoff или явно ограниченной специальной задачи, а не для
автоматического маршрута новой разработки. В новых задачах v2 маршрутизация
этого файла имеет приоритет над требованиями запуска ролей из старых контрактов.

Уже идущие задачи завершаются по snapshot инструкций своей ветки. Не менять
их worktree, конфигурацию родительского workspace, процессы, роли или handoff.
Новая модель применяется после получения этого commit новой задачей либо
после явного перехода завершенной задачи. Не распространять изменения на Integra.
План перехода и наблюдения: docs/agents/TRANSITION.md.

## Границы изменений

- Сверять требования с текущей архитектурой; не ослаблять строгую валидацию SRT,
  cueId, временной шкалы, topics.json, ffprobe и файлов проекта.
- Не запускать Whisper повторно при пригодном full.srt, когда можно продолжить.
- Сохранять чужие изменения; не вмешиваться в активные videotext, whisper-cli,
  ffmpeg, ffprobe и Ollama. Не останавливать общий сервис без явной задачи.
- Изменять HybridTopicAdapter и тематический алгоритм только в явном scope.
- Проверять совместимость старых проектов при изменении схем и ProjectLayout.

## Проверки и выпуск

Единый обязательный контракт: [docs/RELEASE_GATE.md](docs/RELEASE_GATE.md).
Каждая активная роль читает его применимые разделы. Он сохраняет два чистых E2E,
identity, CI cost policy и Owner Test. Документальная задача не запускает сборку.
Проверка регистрации и ссылок: scripts/check_agents.sh.

Задача завершена при доказанном пользовательском результате, релевантных
проверках и документации по фактам; выдача сборки дополнительно требует
полного release gate.

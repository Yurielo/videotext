# Переход VideoText на модель v2

Решение пользователя: пять основных ролей, выборочное делегирование,
сохранение состава Integra и невмешательство в идущие задачи.

## Внедрение

1. Инструкции, регистрация application-developer и валидатор поставляются
   отдельным governance commit/PR. Production-код и release inputs не меняются.
2. После принятия PR новые задачи получают v2 обычным обновлением своей ветки.
   Нельзя перезапускать активные задачи или обновлять их worktree ради перехода.
3. Старые ID и их контракты сохраняются. Основной маршрут использует только
   пять ролей из AGENTS.md; общие release-правила находятся в docs/RELEASE_GATE.md.
4. Конфигурации вне репозитория не синхронизируются автоматически. Новую задачу
   запускают из checkout с v2; при запуске из родительского workspace сначала
   проверяют, какие регистрации реально доступны. Успех статического валидатора
   не является подтверждением загрузки агентского runtime.
5. Архивирование старых ID возможно отдельной задачей после подтверждения,
   что ни один активный handoff не зависит от них. Сейчас они сохраняются.

## Наблюдение на следующих пяти задачах

Координатор добавляет компактный блок в существующий Issue/PR или итоговый отчет:
Issue, тип и риск задачи, примененная версия модели ролей, запущенные агенты
и цель каждого, elapsed time до проверенного результата, обнаруженные дефекты,
число переделок, повторное изучение одного контекста и test gaps.
Токены указываются только при наличии достоверной телеметрии; иначе unavailable.
Не создавать отдельный агент, журнал опросов или тяжелые проверки ради учета.

После пяти завершенных задач сравнить с доступной сопоставимой историей.
Без исходных измерений не заявлять процент экономии. Оценивать одновременно
затраты, время и пропущенные дефекты. Этот документ не создает автоматизацию.

## Готовность перехода

Регистрации и контракты согласованы, валидатор проходит в самостоятельном
checkout без родительских копий, release gate сохранен, старые контракты
не изменены. PR фиксирует commit и проверки. Принятие PR вводит v2 для новых
задач; оно не доказывает переключение уже работающих сессий.
